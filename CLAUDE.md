## Commands

```bash
npm run dev           # Next.js dev server on http://localhost:3000
npm run build         # production build
npm run lint          # ESLint (flat config, next core-web-vitals + typescript)
npm run typecheck     # tsc --noEmit

npm run auth:generate # regenerate Better Auth tables into src/db/schema/auth.ts
npm run db:generate   # drizzle-kit: create SQL migration in ./drizzle from schema
npm run db:migrate    # apply migrations
npm run db:seed       # upsert the sample catalog from src/db/seed-data.ts (idempotent)
npm run db:push       # push schema directly (no migration files; throwaway DBs only)
npm run db:studio     # Drizzle Studio
```

There is no test framework set up yet.

Environment: copy `.env.example` to `.env.local` and fill in `DATABASE_URL` (Neon pooled URL) and `BETTER_AUTH_SECRET`. `drizzle.config.ts` and `db:seed` both read `.env.local`. `next build` needs `DATABASE_URL` too, because `generateStaticParams` queries the products table.

The project uses pnpm (`node_modules` is pnpm-managed); `npx` fails inside it, so CLI tools run via `pnpm dlx`.

Schema changes: edit `src/db/schema/*`, run `db:generate`, review the SQL in `./drizzle`, then `db:migrate`. Commit the migration files.

## Stack

- **Next.js 16.4 (App Router, `src/app`)** with React 19.3. `next.config.ts` enables `cacheComponents` and `partialPrefetching` — read the bundled docs in `node_modules/next/dist/docs/` before relying on caching, data-fetching, or routing behavior from memory. Route prop types use Next's generated global helpers (e.g. `LayoutProps<"/">`).
- **Tailwind CSS v4** loaded through the `@tailwindcss/turbopack` loader configured in `next.config.ts` (no PostCSS config). Theme tokens are defined in `src/app/globals.css` (see Design system below).
- **Drizzle ORM on Neon** (`drizzle-orm/neon-http`). `src/db/index.ts` exports the `db` client with the full schema attached; it throws at import time if `DATABASE_URL` is missing.
- **Better Auth** with email/password and the `nextCookies()` plugin (so server actions can set auth cookies).
- Path alias: `@/*` → `src/*`.

## Architecture

Auth flows through three pieces:
- `src/lib/auth.ts` — server-side `auth` instance using the Drizzle adapter on `db`. Use `auth.api.*` in server components / server actions.
- `src/app/api/auth/[...all]/route.ts` — catch-all route exposing Better Auth's HTTP handlers.
- `src/lib/auth-client.ts` — React client (`authClient`) for client components, pointed at `NEXT_PUBLIC_BETTER_AUTH_URL`.

The Drizzle schema is the `src/db/schema/` folder (re-exported from `index.ts`):
- `auth.ts` is generated by `npm run auth:generate` (user, session, account, verification). Never edit it by hand, and keep app tables out of it, because regeneration overwrites the file.
- `catalog.ts` holds `categories` 1──< `products` 1──1 `product_stock`. Prices are integer cents, `details` is `text[]`, and `images` is ordered `jsonb` (first = primary, at least one enforced by a check constraint). Stock lives in its own table so it can change without touching product rows.

## Design system

Tokens live in the `@theme` block of `src/app/globals.css` and generate Tailwind utilities. The default Tailwind color and radius palettes are reset, so only brand colors exist (`paper`, `surface`, `ink`, `muted`, `line`, `accent`…) and corners are square. Text sizes are semantic (`text-display`, `text-h1`–`h3`, `text-body`, `text-small`, `text-label`), with fluid `clamp()` sizes for headings. Spacing adds fluid `gutter` / `section` steps on top of Tailwind's default scale. Composite styles are `@utility` classes in the same file (`container-page`, `section-y`, `eyebrow`, `btn` + `btn-primary|secondary|inverse|sm|block`, `link-reveal`, `link-underline`).

React primitives that wrap those classes are in `src/components/ui` (import from `@/components/ui`). Never build Tailwind class names with template strings (e.g. `` `btn-${variant}` ``), because the scanner won't generate them. Use a lookup map of full class names instead.

## Storefront structure

- `src/app/layout.tsx` renders the global `SiteHeader` / `SiteFooter` (`src/components/site`) around every page. The mobile menu is a client component rendered through a portal, because the sticky header's `backdrop-filter` would otherwise trap its `position: fixed` overlay.
- Homepage sections live in `src/components/home` and are composed in `src/app/page.tsx`.
- Product pages: `src/app/products/[slug]/page.tsx` prerenders every catalog slug via `generateStaticParams` and reads `params` only inside a `<Suspense>` boundary (with `ProductSkeleton` as fallback), which the Partial Prefetching instant-navigation check requires. `dynamicParams` isn't available with Cache Components, so unknown slugs stream the not-found UI (200 + `noindex`). Parts live in `src/components/product`; `ProductCardGrid` is the shared listing used by both the homepage and the product page.
- Product data comes from `src/lib/products.ts` (server-only): `getProductSlugs`, `getProduct`, `getNewArrivals`, `getRelatedProducts`. Each one is `"use cache"` + `cacheLife("minutes")` + `cacheTag("products")` and maps rows to the `Product` type, so components never import `@/db`. After writing product data, call `revalidateTag`/`updateTag(PRODUCTS_TAG)`.
- Stock state comes from `stockState(product.stock)` in `catalog.ts` (sold out at 0, "Only N left" at ≤3).
- `src/lib/catalog.ts` holds the `Product`/`CatalogImage` types, `formatPrice`, `stockState`, and the non-product content (hero, collections, editorials, navigation; Unsplash photography). Women/Men collections are merchandising tiles, not categories. Sample product data lives in `src/db/seed-data.ts`. Remote images are allowed for `images.unsplash.com` in `next.config.ts`.
- Next 16 deprecates `<Image priority>`. Use `preload` (hero) or `loading="eager"`.
